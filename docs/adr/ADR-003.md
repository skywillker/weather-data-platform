# ADR-003 - Medallion Architecture

## Status

Accepted

## Context

The project initially stored every ingested file inside a single raw directory.

While this approach was enough during the early stages of the project, it does not scale well as new datasets, data sources and processing stages are introduced.

A more structured storage architecture is required to improve organization, support future processing pipelines and enable efficient partition-based queries.

## Decision

Adopt the Medallion Architecture.

All ingested data must be organized according to the Medallion Architecture.

The Bronze layer will:

- store raw JSON files without business transformations;
- organize datasets by domain, dataset and source;
- partition data by ingestion date using Hive-style partitions (year/month/day);
- preserve the original payload for future reprocessing.

## Alternatives Considered

- Keep using a single raw folder.
- Organize files only by date.
- Organize files only by source.

## Rationale

- Preserve the original data.
- Support future Spark transformations.
- Enable efficient partition pruning.
- Improve scalability.
- Simplify future ingestion of additional datasets.


## Consequences

Positive:

- Better organization.
- Easier reprocessing.
- Better scalability.
- Partition pruning support.
- Clear separation between ingestion and storage.

Negative:

- Larger number of folders.
- Slightly more complex directory structure.
- Developers must follow the established directory conventions.
